# Viral marketing campaign solver

Решатель для соревнования по вирусному маркетингу на графе `marketing_edges.txt`.

## Идея стратегии

Задача не сводится к выбору вершин с максимальной степенью. Контракт стоит `300 * degree(v)`, поэтому hub-узлы слишком дорогие, а их абсолютный порог активации высокий.

Используется многошаговая стратегия:

1. Дешевый стартовый bootstrap в день 0.
2. Симуляция порогового распространения.
3. Реинвестирование дохода от вирусных пользователей.
4. Точечная покупка bridge-узлов, когда накопленного бюджета хватает.
5. Stop-rule: поздние дорогие контракты не покупаются, если не успевают окупиться.

В текущей зафиксированной стратегии:

```text
day 0:  3057 3775 2528 2788 154
day 12: 1304
day 16: 2415
day 22: 1398
```

Контрольная симуляция на предоставленном графе дает:

```text
profit: 98700
income: 144300
contract costs: 45600
viral users: 2886
```

## Запуск

Положите рядом с кодом файл `marketing_edges.txt` и, при наличии, `sample_submission.csv`.

```bash
python solve.py --edges marketing_edges.txt --sample sample_submission.csv --out submission.csv
```

Если sample-файла нет, будет создан CSV с колонками `day,node_ids` на 60 дней.

## Проверка

```bash
python solve.py --edges marketing_edges.txt --out submission.csv --print-log
```

Код проверяет:

- не больше 10 контрактов в день;
- узлы существуют в графе;
- контракт не повторяется;
- бюджет не уходит ниже нуля;
- стоимость считается как `300 * degree(v)`.
